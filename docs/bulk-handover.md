# 新規一括集中アシスタント 引継ぎメモ

更新日: 2026-08-25（Ver.1.1）
対象リポジトリ: `https://github.com/glohenshu/GLO_-.git`
対象アプリ: `apps/bulk-assistant`
Vercel Project: `bulk-assistant`（team glo11／Root Directory は `apps/bulk-assistant`）
https://vercel.com/glo11/bulk-assistant/deployments

---

## 1. アプリの目的

新規の一括集中連載をMediaWeaver（MW）で作るときの作業支援ツール。
再掲連載作成アシスタント（`apps/reprint-assistant`）をもとに、参照元の過去連載を持たない形にした。

1. GLO連載情報アプリに新しい連載のカテゴリコード等を登録
2. MWで今回の記事の下書きを作り、採番された記事IDを取得
3. 本アプリにカテゴリコードを入力して連載情報を取得
4. ①タブで回数を決め、記事IDとタイトルを入力
5. ①タブで「前回の記事を読む」HTMLを作る
6. ②タブで「この話の続きを読む＋連載一覧＋イチオシ＋定型文」を作る
7. 各HTMLをMWへ貼り付ける

---

## 2. 再掲連載アシスタントとの違い

| | 再掲（reprint-assistant） | 新規一括集中（bulk-assistant） |
|---|---|---|
| 参照元の過去連載 | 使う（記事データアプリ341から抽出） | **無い** |
| 「続きを読む」の中身 | 参照元の第N+1回 | **①タブに入れた今回の第N+1回** |
| 連載記事一覧の誘導先 | 通常回＝参照元／最終回＝今回 | **全回とも今回のコード** |
| 記事下の週 | 公開予定日から自動判定 | **外部配信日**から自動判定（§7） |
| 公開予定日 | kintoneの第1回配信日時から1日ずつ | **画面の公開グループ**から算出（§7） |
| 分割公開 | 対応しない（毎日更新のみ） | **公開グループ**で分割・毎日に対応（§7） |
| 【注目記事】 | 最終回だけ残す | **全回落とす**（不要） |
| 回ラベル | 最後は「最終回」 | **全回とも第N回** |
| タブ | ①前回記事／②記事下／③次回更新日 | **①前回記事／②この話の続き** |

## 5. API `api/bulk-data.js`

パラメータは3つとも任意。

| 呼び方 | 返るもの |
|---|---|
| `?code=gr1974` | その連載1件（`series`）＋シート |
| `?q=母が母` | 書籍名の部分一致で連載候補（`candidates.items`）＋シート |
| パラメータ無し | **シートだけ** |

```json
{
  "status": "ok",
  "categoryCode": "gr1974",
  "query": "",
  "series": { "status": "ok", "message": "", "data": {} },
  "candidates": { "status": "error", "message": "", "items": [] },
  "sheet": { "status": "ok", "message": "", "rows": [], "rowCount": 80 },
  "warnings": []
}
```

**パラメータ無しでシートだけ返せることが要**（2026-08-25）。
記事下リンクの週は外部配信日だけで決まるので、連載を選ぶ前から作れる。
画面は起動時にこれを呼ぶ（`fetchSheetOnly()`）。

候補検索は kintone の `書籍タイトル like "…"`（部分一致）。上限100件。
`order by` はフィールド名の違いで落ちうるのでクエリに入れず、
レコード番号の降順にJS側で並べ替える。

kintoneとスプレッドシートは互いに独立させる。片方が失敗しても早期returnしない。
`?summary=1` は診断用。rowsを返さず件数と末尾の期間だけ見る。

GASのデプロイは「アクセスできるユーザー＝**全員**」必須。
組織内限定だとログインHTMLが返り `Unexpected token '<'` になる。

## 5-2. 連載の探し方（`#search-input`）

入力欄は1つ。**数字だけならカテゴリコード、それ以外は書籍名の部分一致**に振り分ける
（`isCodeQuery()` → `fetchSeriesData()` / `fetchCandidates()`）。

| 入力 | 動き |
|---|---|
| `1974` / `gr1974` / `GR1974` / `１９７４` | カテゴリコードで1件取得 |
| `母が母` | 書籍名で検索して候補一覧を出す |

候補は書籍タイトル＋カテゴリコード＋制作Noで出す。同じ書籍名が複数あるときの決め手になる。
押すとその連載を読み込み、一覧は閉じる。**カテゴリIDが未登録の候補は押せない**
（選んでも記事下の一覧リンクが作れないため）。

## 6. ① 前回記事リンク作成タブ

列：`回` / `今回の記事ID` / `今回の記事タイトル` / `前回記事` / `操作`

- **カテゴリコードを取得していなくても使える**
- 回数はタブ内の「回数」で決める（`#prev-count`）。1〜200回。全角数字も受ける
- 開いた時点で**10行**できている（`DEFAULT_EPISODE_COUNT`）。一括集中は10回前後が多いため
- **全回とも `第N回`**。一番最後の回だけ `row.isFinal` が立ち、`tr.is-final` が付く
- 記事IDは個別入力と一括貼り付け（1行1ID・空行無視・CRLF可）に対応
- 記事タイトルは任意入力。**プレースホルダーは置かない**（入力済みに見えるため）
- タイトル欄の直下に `18文字` のように `Array.from(value).length` で文字数を出す

生成HTML（再掲側と同じ）:

```html
<p align="center"><a href="/articles/-/30001" target="_blank"><strong><span style="color:#0000CD;">【前回の記事を読む】入力したタイトル</span></strong></a></p>
```

タイトル未入力なら `●▼■` を使う。タイトルはコピーの必須条件ではなく、前回IDがあればコピーできる。

- **第1回はコピーボタン自体を作らない**
- ボタンは `HTMLコピー` → コピー成功後 `コピー済み ✓`（`copied` クラス）。
  **①は回ごとに残す**（どこまで進んだかを一覧で分かるようにするため）。②は最後の1件だけ
- コピー時のHTMLを `row.copiedHtml` に保持し、`syncPrevCopiedState()` で
  現在の生成HTMLと突き合わせて、内容が変われば自動解除する
- 回数を減らして消えた行の入力は `state.idStash` / `state.titleStash` / `state.copiedStash` に
  退避する。`10→8→10` で後半の入力が戻る。一括貼り付けの超過分も退避する
- 空にした行は**空のまま覚える**。消したはずの入力が回数を戻したときに復活しないようにする

## 7. ② この話の続きタブ

列：`回` / `GLO公開` / `外部配信` / `今回の記事ID` / `今回の記事タイトル` /
`この話の続きを読む` / `記事下` / `操作`

**①と同じ作りにする。** 記事ID・記事タイトルの入力欄と文字数カウントを行内に置き、
①と同じ行データを編集する。タブを行き来せずに済ませるため。
回数と記事IDの一括貼り付けも①②の両方に置く（§8）。

タブ内の説明は `<details class="hint-toggle">` で折りたたむ。項目が9つあり、
開いたままだと表が352px下に押し出されるため**既定は閉じ**。開閉はブラウザ任せで、
JSからは触らない。①タブの説明は3項目なので開いたままにしている。

**GLO公開と外部配信は列を分ける**。同じ列に2行で入れると、どちらの日付を見ているか
分かりにくい。日付（曜日つき）と時刻を上下2行にし、色は従属情報の薄いグレーではなく
本文色にする。外部配信の列は地色を敷いて、ずれる側だと見分けられるようにしている。

出来上がりの並び（`joinBottomHtml()`）:

```html
<p>　</p>

<p>▶この話の続きを読む<br />
<span style="font-size:18px;"><a href="/articles/-/30002" target="_blank"><span style="color:#0000FF;">次の回のタイトル</span></a></span></p>

<p><span style="font-size:20px;">👉<a href="/category/gr1974" target="_blank"><span style="color:#0000FF;">『書籍名』連載記事一覧は<u>こちら</u></span></a></span></p>

<p><a href="/articles/-/40001" target="_blank"><strong><span style="color:#0000CD;">【イチオシ記事】</span></strong></a></p>

<p>　</p>

<p>ゴールドライフオンライン（GLO）は、表現者を応援するウェブメディアです。…</p>
```

- **続きを読む＝①タブの第(N+1)回**のID・タイトル。回数で対応させる
- 次の回のラベルは①と揃える（第N回）。「最終回」とは呼ばない
- 次の回のタイトルが未入力なら `●▼■` を使う。**記事IDが未入力ならコピーを止める**
- 連載一覧・イチオシ・定型文はスプレッドシートC列。**イチオシはC列そのまま**
- C列先頭の余白 `<p>　</p>` は**先頭へ回して**、続きを読むの上に空きを作る。
  `<p>&nbsp;</p>` や `<p align="center">　</p>` も余白とみなす

### 公開予定日時と公開グループ（`#pub-group-body`）

「新規一括集中連載管理シート」と同じ計算にする。
1本の連載を何回かに分けて一括公開することがある（管理シートでも第1〜10回が8/18、
第11〜14回が8/31になっている）ため、**「この回から」で区切ったグループごとに**計算する。

グループの持ち物（`state.pubGroups`）:

```js
{ startNumber: 11, date: '2026-08-31', mode: 'bulk' | 'daily', time: '14:00' }
```

**時刻はGLO公開・外部配信で共通**（`time` 1つだけ）。分ずらしが乗るのはGLO公開だけ。

| 方式 | GLO公開 | 外部配信 |
|---|---|---|
| `bulk`（一括） | 開始日でそろえ、時刻を**1分ずつ**足す | 開始日から**1日ずつ**。時刻はそのまま |
| `daily`（毎日） | 開始日から**1日ずつ**。分ずらし無し | GLO公開と**同一** |

対応する運用パターン（2026-08-25 に運用側で確定）:

1. 日付を変えて同じロジックで追加 → `bulk`／日付だけ変える
2. 時刻も変わる → `bulk`／`time` を変える（例：21:00 → 14:00）。
   **「公開時刻と外部配信時刻を別々にする」という意味ではない**
3. 毎日連載に切り替える → `daily`

- **ずらしの起点はグループごとに戻る**。第11回はまた `14:00` から、外部配信も開始日から
- グループは次のグループの開始回の**手前まで**を受け持つ。最後のグループは一番最後の回まで
- 分が60を超えたら時に繰り上がる（21:00 + 69分 = 22:09）。月・年またぎも Date に任せる
- 既定は1グループだけ（第1回から・今日・21:00・一括）。`initPubFields()`
- 日付か時刻が読めないときは、そのグループの回だけ公開予定を出さずコピーも止める

**画面の入力をそのまま計算に使わない。** 必ず `normalizePubGroups()` を通す。
開始回で並べ替え、先頭は必ず第1回にし、開始回が重なったら1つ後ろへずらす。
これを飛ばすと、逆順や重複でグループが0回になって日付が入らない回ができる。

2つ目以降のグループの先頭行には `tr.is-group-start` を付けて区切り線を出す
（`isGroupStartRow()`）。`#pub-status` にはグループごとの範囲を1行で出す。

### 記事下リンクの週

**外部配信日で判定する。GLO公開日ではない。**
GLO公開日は全回同じなので、そちらで引くと全回が同じ週のイチオシになってしまう。

判定は reprint-assistant と同じ実装（`parsePeriodParts()` / `assignRowYears()` /
`findSheetRowForRow()`）。B列に年が無く1年以上分が積み上がっているため、
**B列の曜日で採点して行ごとの年を推定してから**突き合わせる。
「今日に近い年」だけで決めるとシート未更新時にずれる。

- B列の期間表記は3形式（`8/23（日）〜8/29（土）` / `6/1（日）～7（土）` / `4/1～15`）。
  波ダッシュも `～`(U+FF5E) と `〜`(U+301C) が混在
- 年またぎ（12/28〜1/3）は終了側の月が開始より小さければ年を+1する
- **該当行が無いときは黙って別の行を使わず**「該当期間が見つかりません」を出してコピーを止める
- 画面には `2026/8/16〜2026/8/22` の1行だけ出す。B列の原文と外部配信日はツールチップで見る

### 【イチオシ / 注目 / 人気】ルール

| | 全回 |
|---|---|
| 連載記事一覧 | 残す |
| 【イチオシ記事】 | 残す |
| 【注目記事】 | **落とす** |
| 【人気記事】 | **落とす** |
| GLO定型文 | 残す |

**このプロジェクトでは【注目記事】は不要**（2026-08-25 に運用側で確定）。
最終回だけ【注目記事】を残す再掲連載アシスタント（`docs/reprint-handover.md` §12）とは違い、
`removeDroppedParagraphs()` は**回によらず両方落とす**。回で分岐させないこと。

判定は必ず `【注目記事】` `【人気記事】` という記事ラベルで行う。
「注目」「人気」だけで判定すると書籍タイトルの `［注目連載ピックアップ］` まで巻き込む。

### プレースホルダー置換

C列HTML内の `grxxxx` `gr●●●●` をカテゴリコードへ、`xxxxxxxx` `●●●●●●●●` を書籍タイトルへ置換する。
`gr●●●●`（4個）を先に処理する。`●●●●●●●●`（8個）を先に置換すると壊れる。
書籍タイトルの `『』` 二重化と `［注目/人気連載ピックアップ］` は外す。

### 一番最後の回

```html
<p align="center">試し読み連載は今回で最終回です。ご愛読ありがとうございました。</p>
```

**このプロジェクトでは「最終回」という回ラベルを使わない**（2026-08-25 に運用側で確定）。
全回とも `第N回`。回数を14にすれば第14回まで並ぶ。

そのうえで、**一番最後の回だけ**続きのリンクの代わりにこの文言が入る
（`row.isFinal` ／ `FINAL_MESSAGE`）。文言は固定で、選択欄は置かない。
その行の「この話の続きを読む」欄には**文言を表示しない**（`—` を出す）。
表示すると、そのまま記事下に貼る文だと誤解されるため。

### コピーを止める条件

誤ったHTMLを作るくらいなら止める。理由はボタンのツールチップに出す。

| 状態 | 理由 |
|---|---|
| シートを取得する前 | `カテゴリコードを取得してください（記事下リンクと連載情報に使います）` |
| 次の回の記事IDが未入力 | `第N回の記事IDが未入力です` |
| シートが取れていない | `記事下データを取得できませんでした（…）` |
| そのグループの開始日・時刻が未入力 | `このグループの開始日と時刻を入力してください` |
| 該当週がシートに無い | `記事下リンクの該当期間が見つかりません（外部配信日 …）` |
| 該当週のC列が空 | `記事下リンクのC列が空です` |
| 連載情報が未取得 | `連載情報を取得してください` |

最後の1つが要るのは、連載情報が無いと `grxxxx` `xxxxxxxx` が置換されずに残るため。

## 8. 壊してはいけない実装

- 記事IDが未入力の回はコピーボタンを無効にする。誤ったリンクを貼らせない
- タイトルは `escapeHtml()` を通す（`&` `<` `>` `"`）
- **回数と記事IDの入口は①②に2つあるが、データは1つ**。
  回数は `state.episodeCount`、記事IDは `state.rows` を両方が見ている。
  `bindCountControl()` / `bindBulkControl()` で同じ処理に配線し、
  `renderCountControl()` は両方の入力欄を書き換える。
  貼り付け欄の文字列は `syncBulkInputs()` で、結果表示は `setBulkStatus()` で揃える。
  **別々の入力欄として実装しないこと。** 二重に貼られて回数がずれる
- **同じ行を①②の2か所に出している**。要素の参照は `row.el`（①）と
  `row.elBottom`（②）に分けて持つ。入力は `handleRowInput()` が1か所で受け、
  値・文字数・もう片方の入力欄・影響する行をまとめて更新する
- **入力のたびに②の表ごと作り直さない**。作り直すと打っている入力欄から
  フォーカスが外れる。`updateBottomRow(index)` で影響する行だけ差し替える。
  ①の前回記事は1つ後ろの行に、②の続きを読むは1つ前の行に効く
- **「まだ取得していない」と「取得に失敗した」を書き分ける**（`state.sheetFetched`）。
  起動直後に「スプレッドシートを取得できませんでした」と出すと、
  原因を探しに行かせてしまう
- **記事下リンクは連載を選ぶ前から作れる**。週は外部配信日だけで決まるので、
  起動時に `fetchSheetOnly()` でシートだけ取る。
  APIを `?code=` 必須に戻さないこと
- **起動時のシート取得は表を作り直さず `markBottomDirty()` を通す**。
  応答は読み込みの少しあとに返るので、②を開いていないのに作り直すと
  入力中の表を壊しうる
- **表の中身は必ず `.line` に入れる**（`createLine()`）。`.line` は折り返さず端で省略し、
  全文は title でホバー表示する。素のテキストを td に直接入れると、
  列幅が固定なので隣の列に文字が重なって出る
- **列幅を変えるときは `@media (max-width: 900px)` の方も直す**。
  そちらが後ろにあるので上書きされる。「第100回」「GLO 8/25 21:00」が
  入る幅を切らないこと
- **①②に同じ形で置く部品のCSSはID指定にしない**。
  `#bulk-input` と書くと片方にしか効かず、②だけ枠が素の見た目になる。
  `.bulk textarea` のようにクラスで当てる
- **カテゴリコードを取得しても①の入力は消さない**。
  消すのは**別のカテゴリコードに切り替えたときだけ**（`clearAllInputs()`）。
  先に回数と記事IDを入れてから取得する使い方があるため
- ①の入力は②の「続きを読む」に効く。①を触っている間は②を作り直さず、
  `state.bottomDirty` に印を付けて②を開いたときにまとめて描き直す
- `switchTab()` は `TAB_NAMES` に無い名前を弾く。③を足すときは
  `TAB_NAMES` と `el` のパネル参照を両方増やすこと
- **記事下の週はGLO公開日ではなく外部配信日で引く**。GLO公開日は全回同じなので、
  そちらで引くと全回が同じ週のイチオシになる
- 起動時の描画（`initPubFields()` / `setEpisodeCount()` / `renderBottomTable()`）は
  **app.jsの末尾**で呼ぶ。`PREV_TITLE_FALLBACK` などの `const` より前に呼ぶとTDZで落ちる。
  `initPubFields()` は `setEpisodeCount()` より先に呼ぶ（行を作るときに日付を計算するため）
- 参照元タイトルの記号は自動で直さず「要確認」を出すだけにする（`findRiskyTitleParts()`）
