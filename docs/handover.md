# 新連載作成アシスタント Ver.1 引継ぎメモ

**更新日：2026/08/18**

## 1. 概要

GLOの新規連載登録時に必要な情報を、カテゴリコードを起点に自動取得・整形する社内ツール。

本番URL：

`https://shinrensai-assistant.vercel.app/`

カテゴリコード（例：`gr1966`）を入力して「情報取得」を押すと、主に以下から情報を取得する。

| 取得元 | 用途 |
|---|---|
| kintone「GLO連載情報」 | 書籍タイトル、カテゴリID、制作No.、第1回配信日時、出版実績URL |
| 出版実績ページ | 著者紹介、内容紹介、ISBN、判型、出版年月日、カテゴリ説明用キャッチ |
| Googleスプレッドシート「毎月の記事下リンク」 | 本文テンプレート末尾HTML |
| Vercel環境変数 | 記事下リンク確認URL、MediaWeaver確認URL等 |

kintoneではカテゴリIDを完全一致で検索し、レコードに登録されている「出版実績URL」を直接利用する。

## 3. ここまで対応済み

### API処理順の修正

一時期、kintone取得直後に `res.status(200).json(result)` を返してしまい、出版実績とスプレッドシートが常に未取得になる問題があった。

現在は以下の順に修正済み。

```text
kintone
↓
出版実績
↓
記事下リンク
↓
確認用リンク生成
↓
JSON返却
```

### kintone直リンク

取得した `$id` を使って、該当レコードへの直リンクを生成するようにした。

```text
/k/{APP_ID}/show#record={recordId}
```

### 記事下リンクURL

`ARTICLE_SHEET_URL` は以下どちらでも使用可能。

- Googleスプレッドシートの完全URL
- スプレッドシートIDのみ

IDのみの場合は、アプリ側でGoogleスプレッドシートURLへ変換する。

### 著者名の誤判定対策

以前、著者紹介本文の以下のような行が著者名として誤認される問題があった。

```text
1985年 バングラデシュ正規派遣（専門：ハンセン病 ハンセン病外科）
```

現在は著者名行について、

- `名前（かな）` 形式
- 名前先頭が数字ではない
- 括弧内がひらがな・カタカナ等で構成されている
- 異常に長い文字列ではない

という条件で判定するように変更済み。

### サマリー本文

「④サマリー作成」の本文（編集用）は、内容紹介から**改行・空行を削除して一続きの文章として表示**するよう変更済み。

出典文の著者名については半角スペースを除去している。

### 本文テンプレート

記事下リンク表C列のHTML内プレースホルダーを置換するよう対応済み。

カテゴリID：

```text
grxxxx
gr●●●●
```

書籍タイトル：

```text
xxxxxxxx
●●●●●●●●
```

タイトル自体に `『』` が付いている場合は、テンプレート側の `『』` と二重にならないよう除去する。

## 4. 現在対応途中の箇所

### 4-1. カテゴリ説明の取得方法

従来は、カテゴリ説明用キャッチを探す際にkintoneの書籍タイトルを出版実績ページ本文から検索していた。

この方式だと、

```text
kintone：
「共感と信頼のサステナ経営」

出版実績ページ：
共感と信頼のサステナ経営
```

のように括弧の有無が違うだけで取得失敗する。

現在の方針は以下。

```text
カテゴリID
↓
kintoneレコード
↓
登録済み出版実績URL
↓
そのページ自身の <h1>
↓
h1直後からキャッチを抽出
```

**タイトル部分一致で出版実績を探すことはしない。**

出版実績ページ自体はkintoneに登録済みのURLで確定し、ページ内解析のみ `<h1>` を基準にする。

この方式の `fetch-info.js` 修正版は作成済み。  
**→ 2026/08/18、push済み・本番動作確認まで完了。**

- 実装コミット：`e1ffc95 Use publication h1 for catch copy`
- `main` と `origin/main` は同一（未pushの差分なし）
- 実装箇所：`api/fetch-info.js` の `extractMainH1()` と `parsePublicationPage()` 内のキャッチ抽出

### 4-2. 書籍登録「紹介文」の `<br>` 二重問題

現在、②書籍登録の紹介文は元の内容紹介を改行ごとに `<br>` へ変換している。

元データに空行がある場合、

```html
文章1<br>
<br>
文章2<br>
<br>
文章3
```

となる。

希望仕様：

```html
文章1<br>
文章2<br>
文章3
```

対応案：

```js
function textToBrCompact(text) {
  const lines = String(text || '')
    .replace(/\r\n?/g, '\n')
    .split('\n')
    .filter((line) => line.trim() !== '');

  return lines.join('<br>\n');
}
```

書籍登録の紹介文だけ `textToBrCompact()` を使用する。

著者紹介は別ルールのため、既存 `textToBr()` は残す。

**→ 2026/08/18、反映・確認まで完了。**

- `app.js` に `textToBrCompact()` を実装済み
- `BOOK_FIELD_DEFS` の `intro`（紹介文）にのみ適用済み  
  `{ key: 'intro', label: '紹介文', textarea: true, calc: () => textToBrCompact(state.pub?.intro || '') }`
- 著者紹介側は既存 `textToBr()` のまま（変更なし）
- 本番配信中の `app.js` がローカルの `app.js` と完全一致することを確認済み

検証：`gr1966` の内容紹介は実データに空行が3か所ある。  
この入力で出力が `<br>` 1つ区切りになり、`<br><br>` が発生しないことを確認した。

#### ❌ 発見した不具合（**すべて 2026/08/18 修正済み**）

| # | 不具合 | 件数 | 修正箇所 |
|---|---|---|---|
| 1 | **判型に「出版年月日」が混入** | 39 | `api/fetch-info.js` `FIELD_LABELS_RE` |
| 2 | **著者名検出0（かな括弧なし）** | 12 | `app.js` フォールバック |
| 3 | **著者名が半角括弧だと検出不可** | 2 | `app.js` `parseNameLine` |
| 4 | **`■著者略歴` を認識せず著者紹介が空** | 1 | `api/fetch-info.js` `AUTHOR_HEADINGS` |
| 5 | **内容紹介が `■` 小見出しで途切れる** | 2 | `api/fetch-info.js` `cutAtStops(text, keepSubHeadings)` |
| 6 | **ソフト404ページから宣伝文をキャッチとして取得** | 1 | `api/fetch-info.js` `h1.title` ガード |

**1. 判型に「出版年月日」が混入（39件）**

正規表現 `/判型[：:\s]*([^\n]+)/` の `\s` が改行を含むため、判型が空欄の
ページ（電子書籍のみの作品）でラベルを飛び越えて次行「出版年月日」を拾っていた。

```text
ISBN
判型          ← 値が空
出版年月日     ← これを判型の値として取得してしまう
2026/7/31
```

②書籍登録の「判型」欄に `出版年月日` と入るため、そのまま貼ると誤登録になる。

**⚠️ 今後ここを触るときの注意：`出版年月日` の取得は同じ「改行またぎ」に
依存して正しく動いている**（ラベルの次行が値）。改行またぎを単純に禁止すると
出版年月日が壊れる。そのため修正は「改行またぎは残したまま、
取得値が既知のラベルなら空にする」方式にしてある（`FIELD_LABELS_RE`）。

**2. 著者名検出0（12件）**

例：`gr1868`（えんどう としこ）／`gr1879`（いつむ）／`gr1966`（ふらり）

`名前（かな）` 形式でないペンネームは検出されず、フォールバックが
ブロック全体を著者紹介に入れるため、**著者名・かなが空欄になり、
紹介文の先頭に名前が残っていた**。②の「著者」「表示用著者名」も空になる。

修正後は、名前行が1件も見つからない場合に限り
先頭行を著者名・以降を著者紹介として分離する（かなは空のまま手入力）。

判定は「先頭行が40字以内かつ数字始まりでない」こと。
行数は条件にしていない（`gr1764` のように経歴が無く名前1行だけのページがあるため）。
数字始まりの散文だけのブロックは従来どおり著者名にせず、全文を著者紹介に入れる。

なお `gr1949` は `長谷川 潔（はせがわ きよし）（本名：清）` と括弧が2つ連なるため
かな判定に通らず、このフォールバック経由で**全体が著者名欄に入る**。
空欄よりはましだが、手で整える必要がある。

**3. 著者名が半角括弧（2件）**

該当：`gr1866`（`夕凪 丹麗(ゆうな あかり)`）／`gr1712`（`輪月 舟(わづき しゅう)`）。
`parseNameLine` が全角 `（）` のみ対応だったため検出できなかった。

**4. `■著者略歴`（1件）**

該当：`gr1941`（アンドロギュノス）。ページ側の見出しが `■著者紹介` ではなく
`■著者略歴`。著者情報が丸ごと取得できていなかった。

**5. 内容紹介が `■` で途切れる（2件）**

該当：`gr1873`（金星への帰還）／`gr1760`（認知症介護エッセイ）。
内容紹介の中に `■5台のカメラ開発秘話` のような小見出しリストがあり、
最初の `■` で打ち切られていた。`gr1760` は末尾2段落ごと欠落していた。

**6. ソフト404ページから宣伝文をキャッチとして取得（1件）**

該当：`gr1702`（えつの大きなひとりごと。）。
削除済み商品のURLは **HTTP 200 のまま `<h1>` の無い404ページ**が返る。
このとき `og:description` フォールバックが働き、
「幻冬舎グループの編集力・プロモーション・流通力／…」というサイト共通の
宣伝文をキャッチコピーとして返していた。

**一見それらしい日本語が入るため、誤りに気づきにくい**のが危険だった。
修正後は `<h1>` が取れないページを出版実績ページとみなさず、全項目を空にする。

#### 補足：不具合ではなかったもの

- **キャッチ複数行** — 実際に複数行のキャッチが掲載されているページで、取得結果は正しい
- **ISBN空・判型空** — 「電子書籍のみ」の作品。ページ自体に記載がない
- **内容紹介空（`gr1709`）／著者紹介空（`gr1714`）** — ページに当該セクションが存在しない
- **出版実績URL未登録（58件）** — ピックアップ企画・コンテスト連載・記念企画など、
  そもそも書籍の出版実績ページが存在しない案件。仕様どおりの挙動
