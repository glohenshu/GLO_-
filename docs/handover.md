# 新連載作成アシスタント Ver.1 引継ぎメモ

**更新日：2026/08/18**

## 1. 概要

GLOの新規連載登録時に必要な情報を、カテゴリコードを起点に自動取得・整形する社内ツール。

本番URL：

`https://shinrensai-assistant.vercel.app/`

カテゴリコード（例：`gr1966`）を入力して「情報取得」を押すと、主に以下から情報を取得する。

| 取得元 | 用途 |
|---|---|
| kintone「GLO連載情報」 | 書籍タイトル、カテゴリID、制作No.、第1回配信日時、出版実績URL |
| 出版実績ページ | 著者紹介、内容紹介、ISBN、判型、出版年月日、カテゴリ説明用キャッチ |
| Googleスプレッドシート「毎月の記事下リンク」 | 本文テンプレート末尾HTML |
| Vercel環境変数 | 記事下リンク確認URL、MediaWeaver確認URL等 |

kintoneではカテゴリIDを完全一致で検索し、レコードに登録されている「出版実績URL」を直接利用する。

## 3. ここまで対応済み

### API処理順の修正

一時期、kintone取得直後に `res.status(200).json(result)` を返してしまい、出版実績とスプレッドシートが常に未取得になる問題があった。

現在は以下の順に修正済み。

```text
kintone
↓
出版実績
↓
記事下リンク
↓
確認用リンク生成
↓
JSON返却
```

### kintone直リンク

取得した `$id` を使って、該当レコードへの直リンクを生成するようにした。

```text
/k/{APP_ID}/show#record={recordId}
```

### 記事下リンクURL

`ARTICLE_SHEET_URL` は以下どちらでも使用可能。

- Googleスプレッドシートの完全URL
- スプレッドシートIDのみ

IDのみの場合は、アプリ側でGoogleスプレッドシートURLへ変換する。

### 著者名の誤判定対策

以前、著者紹介本文の以下のような行が著者名として誤認される問題があった。

```text
1985年 バングラデシュ正規派遣（専門：ハンセン病 ハンセン病外科）
```

現在は著者名行について、

- `名前（かな）` 形式
- 名前先頭が数字ではない
- 括弧内がひらがな・カタカナ等で構成されている
- 異常に長い文字列ではない

という条件で判定するように変更済み。

### サマリー本文

「④サマリー作成」の本文（編集用）は、内容紹介から**改行・空行を削除して一続きの文章として表示**するよう変更済み。

出典文の著者名については半角スペースを除去している。

### 本文テンプレート

記事下リンク表C列のHTML内プレースホルダーを置換するよう対応済み。

カテゴリID：

```text
grxxxx
gr●●●●
```

書籍タイトル：

```text
xxxxxxxx
●●●●●●●●
```

タイトル自体に `『』` が付いている場合は、テンプレート側の `『』` と二重にならないよう除去する。

## 4. 現在対応途中の箇所

### 4-1. カテゴリ説明の取得方法

従来は、カテゴリ説明用キャッチを探す際にkintoneの書籍タイトルを出版実績ページ本文から検索していた。

この方式だと、

```text
kintone：
「共感と信頼のサステナ経営」

出版実績ページ：
共感と信頼のサステナ経営
```

のように括弧の有無が違うだけで取得失敗する。

現在の方針は以下。

```text
カテゴリID
↓
kintoneレコード
↓
登録済み出版実績URL
↓
そのページ自身の <h1>
↓
h1直後からキャッチを抽出
```

**タイトル部分一致で出版実績を探すことはしない。**

出版実績ページ自体はkintoneに登録済みのURLで確定し、ページ内解析のみ `<h1>` を基準にする。

この方式の `fetch-info.js` 修正版は作成済み。  
**本番への置換・push・動作確認が完了したかは要確認。**

#### 最優先テスト

カテゴリID：

```text
gr1945
```

書籍：

```text
「共感と信頼のサステナ経営」
```

期待するカテゴリ説明：

```text
利益を追わない企業に、未来はない。利益だけ追う企業にも、未来はない。
```

### 4-2. 書籍登録「紹介文」の `<br>` 二重問題

現在、②書籍登録の紹介文は元の内容紹介を改行ごとに `<br>` へ変換している。

元データに空行がある場合、

```html
文章1<br>
<br>
文章2<br>
<br>
文章3
```

となる。

希望仕様：

```html
文章1<br>
文章2<br>
文章3
```

対応案：

```js
function textToBrCompact(text) {
  const lines = String(text || '')
    .replace(/\r\n?/g, '\n')
    .split('\n')
    .filter((line) => line.trim() !== '');

  return lines.join('<br>\n');
}
```

書籍登録の紹介文だけ `textToBrCompact()` を使用する。

著者紹介は別ルールのため、既存 `textToBr()` は残す。

**反映・確認が必要。**

## 5. 今後必ず行いたい検証

| ケース | 確認内容 |
|---|---|
| 通常の単著 | 著者名・かな・紹介文が正しく分離される |
| 著者紹介内に括弧あり | 本文が別著者として誤認されない |
| 複数著者 | 著者カードが人数分生成される |
| タイトルに「」あり | カテゴリ説明が取得できる |
| タイトルに『』あり | 同上 |
| 出版実績にサブタイトルあり | キャッチ部分だけ取得できる |
| 出版実績のHTML構造が少し違う | 誤った文章をキャッチとして取得しない |
| 内容紹介に空行あり | 書籍登録で `<br><br>` にならない |
| サマリー | 改行・空行なしで本文が表示される |
| 記事下リンク | 第1回配信日が該当期間と正しく一致する |
| 年またぎ | 12月末～1月初の期間判定が正しい |
| 確認用リンク | kintone／出版実績／記事下リンク／MediaWeaverが開く |
| API一部失敗 | 1ソース失敗しても他の情報取得を継続する |

## 6. UIについて

現時点では機能追加を優先して作っているため、**UIは今後もう一段変更したい**。

一度、上部領域が縦に長くなりすぎたため、

- 基本情報のpadding縮小
- 検索エリアの余白縮小
- 確認用リンクを折りたたみ式に変更
- タブまでの余白を縮小

というコンパクト化を行った。

ただし最終形としては、単純に余白を削るだけでなく、**作業導線そのものを見直したい**。

| 現状 | 今後の方向 |
|---|---|
| 上部に情報が集中している | 必要最低限だけ常時表示 |
| 確認リンク | 折りたたみ維持 |
| 解析デバッグ | 通常利用では邪魔なので折りたたみ／非表示候補 |
| 5タブ | 今の順番が実作業フローと合うか再検討 |
| コピー操作 | よく使うものを目立たせたい |
| 長いtextarea | 内容量によって見づらいので高さ・自動調整を検討 |
| 取得成功／失敗表示 | より短く、視認しやすくしたい |

方向性としては、**「開発ツールっぽい画面」より「作業手順に沿って迷わず登録できる業務ツール」へ寄せる。**

## 8. Vercel・Git運用

VercelのSource画面から直接コード編集する運用ではなく、現在はGitHub経由。

基本フロー：

```bash
git add .
git commit -m "修正内容"
git push origin main
```

`main` にpushするとVercelが自動デプロイする。

修正後はVercelが `Ready` になったことを確認してから本番画面を再読み込みする。

APIだけ確認したい場合：

```text
https://shinrensai-assistant.vercel.app/api/fetch-info?code=gr1966
```
