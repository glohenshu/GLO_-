## 1. アプリの目的

完成済みの再掲連載を閲覧するツールではなく、**これからMediaWeaver（MW）で再掲記事を作るための業務支援ツール**。

1. GLO連載情報アプリに新しい再掲連載のカテゴリコード等を登録
2. 本アプリにカテゴリコードを入力
3. 同一書籍の過去連載を参照元候補として自動抽出
4. 参照元連載をユーザーが手動選択
5. 再掲連載回数を参照元回数から自動設定しつつ、必要に応じて手動増減
6. MWで今回の再掲記事下書きを作り、採番された記事IDを取得
7. 「前回記事」タブでID・タイトルを入力
8. 1つ前の回のID・タイトルから「前回の記事を読む」HTMLを生成
9. 「記事下」タブで「続きを読む＋連載一覧＋イチオシ等」を生成
10. 各HTMLをMWへ貼り付け

今回作る再掲記事は、作業開始時点では記事データアプリに存在しない前提。

## 6. 記事下シートの期間判定

B列例:

```text
9月第一週
8/30（日）〜9/5（土）
```

- 先頭の「9月第一週」等は無視
- `～`(U+FF5E) / `〜`(U+301C) の両方に対応
- 表記は3形式（`8/23（日）〜8/29（土）` / `6/1（日）～7（土）` / `4/1～15`）
- 年またぎ対応（終了側の月が開始より小さければ年を+1）
- **最終行から先頭へ検索**し、同一期間が複数あれば最も下の行を採用
- **B列に年が無いため `assignRowYears()` で行ごとの年を推定してから突き合わせる**
- **年の推定はB列の曜日で採点して決める**。「今日に近い年」だけで決めるとシート未更新時にずれる
- 該当行が無いときは黙って別の行を使わず「該当期間が見つかりません」を出す

画面表示は `2026/8/23〜2026/8/29` の1行だけ。
B列の原文と誘導先はツールチップ（ホバー）で確認できる。

## 7. 再掲連載回数の手動調整

- 初期値＝参照元の記事数／最小1・上限200／直接入力可／全角数字対応／↑↓キー対応
- 参照元との差分表示と「参照元の回数に戻す」ボタン
- N回設定時は `第1回〜第(N-1)回＋最終回`
- 回数変更時も入力済みID・タイトルを `state.idStash` / `state.titleStash` / `state.copiedStash` に退避
- `10→8→10` で後半の入力を復元。一括貼り付けの超過分も退避する

## 8. 公開予定日時

GLO連載情報の `第1回配信日時` を日本時間で読み、毎日更新として +1日ずつ算出する。
前回記事タブでは表示しない。記事下タブでは期間判定に使い、表示もする。

## 9. ① 前回記事タブ

列：`回` / `今回の記事ID` / `今回の記事タイトル` / `前回記事` / `操作`

- 記事IDは個別入力と一括貼り付け（1行1ID・空行無視・CRLF可）に対応
- 記事タイトルは任意入力。**プレースホルダーは置かない**（入力済みに見えるため）
- タイトル欄の直下に `18文字` のように `Array.from(value).length` で文字数を出す
- 第2回以降は1つ前の回のID・タイトルを参照する

生成HTML:

```html
<p align="center"><a href="/articles/-/27332" target="_blank"><strong><span style="color:#0000CD;">【前回の記事を読む】入力したタイトル</span></strong></a></p>
```

タイトル未入力なら `●▼■` を使う。タイトルはコピーの必須条件ではなく、前回IDがあればコピーできる。

- **第1回はコピーボタン自体を作らない**
- ボタンは `HTMLコピー` → コピー成功後 `コピー済み ✓`（`copied` クラス）
- コピー時のHTMLを `row.copiedHtml` に保持し、`syncPrevCopiedState()` で
  現在の生成HTMLと突き合わせて、内容が変わればコピー済みを自動解除する

## 10. ② 記事下タブ

### この話の続きを読む

今回 第N回 → 参照元 第N+1回。公開日時ではなく回数で対応させる。

```html
<p>▶この話の続きを読む<br />
<span style="font-size:18px;"><a href="/articles/-/記事ID" target="_blank"><span style="color:#0000FF;">記事タイトル</span></a></span></p>
```

設定した最後の行は、参照元に次回が残っていても必ず最終回扱い。
参照元回数を超えた場合は「参照元に該当回がありません」を出し、誤ったHTMLは作らない。

### 最終回メッセージ

```html
<p align="center"><span style="font-size:16px;">試し読み連載は今回で最終回です。</span></p>
```

直後の余白 `<p>　</p>` はスプレッドシートC列の先頭に入っているため、ここでは出さない。
（gr1896・gr1528 の公開記事で確認済み）

### 連載記事一覧リンク

**カテゴリコードは回によって変える。書籍名は常にピックアップ表記を外す。**

| | リンク先 | 表示タイトル |
|---|---|---|
| 通常回 | `/category/参照元コード` | `『書籍名』` |
| 最終回 | `/category/今回のコード` | `『書籍名』` |

例（今回 gr1974／参照元 gr1334）:

```text
通常回 → /category/gr1334　『七つのショートしょーと』
最終回 → /category/gr1974　『七つのショートしょーと』
```

理由：通常回の時点では今回の再掲一覧がまだ完成していないため参照元一覧へ誘導する。
最終回では今回の再掲一覧が揃うため現連載へ誘導する。

**書籍名に `［注目連載ピックアップ］` `［人気連載ピックアップ］` は入れない。**
公開済みの gr1896・gr1528 は通常回・最終回とも『プレナイト』と表示していた（2026-08-19 突合で確認）。

## 11. 記事下【イチオシ / 注目 / 人気】ルール

| | 通常回 | 最終回 |
|---|---|---|
| 参照元／今回の連載一覧 | 残す | 残す |
| 【イチオシ記事】 | 残す | 残す |
| 【注目記事】 | **落とす** | **残す** |
| 【人気記事】 | 落とす | 落とす |
| GLO定型文 | 残す | 残す |

実装は `DROP_ATTENTION_RE` / `DROP_POPULAR_RE` と `removeDroppedParagraphs(html, isFinal)`。
最終回は人気だけ、通常回は注目＋人気を落とす。**全回共通で注目を落としてはいけない。**

判定は必ず `【注目記事】` `【人気記事】` という記事ラベルで行う。
「注目」「人気」だけで判定すると書籍タイトルの `［注目連載ピックアップ］` まで巻き込む。

## 12. 記事下プレースホルダー置換

C列HTML内の `grxxxx` `gr●●●●` をカテゴリコードへ、`xxxxxxxx` `●●●●●●●●` を書籍タイトルへ置換する。
`gr●●●●`（4個）を先に処理する。`●●●●●●●●`（8個）を先に置換すると壊れる。
書籍タイトルの `『』` 二重化は防止する。

## 13. 参照元タイトルの確認

記事データアプリの記事タイトルは、そのまま貼るとMWに入る。原稿由来の記号が残っていることがあるため：

- 「参照元 第2回／ID 20654」を**実記事へのリンク**にしてある（`記事URL` を使い、
  空なら同じ連載の他記事からURLの形を借りる。作れなければリンクにしない）
- タイトルに以下が含まれるとき「要確認」の目印を出す（自動では直さない）
  - HTMLで意味を持つ記号（`&` `<` `>` `"`）
  - `??` の連続（**`――` の文字化け**。gr1528に8件実在）
  - 半角カナ／機種依存の記号／文字化け（U+FFFD）／制御文字
- 半角の `!` `?` 単体や `!?` `!!` は通常の表記なので対象にしない

## 18. 設計方針

完全自動化ではなく、**機械的に決められる部分は自動化し、運用判断が必要な部分は人が調整できる**ことを優先する。

- 参照元候補 → 自動抽出、選択は手動
- 再掲回数 → 参照元回数を初期値、増減可
- 公開予定日 → 第1回配信日時から自動算出
- 前回記事 → MWで採番されたID・タイトルを入力
- 記事下 → 期間判定・HTML加工を自動化
- 対応不能な参照元回 → 勝手に推測せずエラー表示
- 参照元タイトルの記号 → 自動で直さず「要確認」を出す

誤ったHTMLを自動生成するより、判断不能時は明示して止める。
